# 流量统计

[返回文档首页](README.md) · [English](../traffic-accounting.md)

Hostpin 将瞬时网络速率与计费周期流量分开。Agent 上报累计接收/发送计数器，服务端
计算周期总量，从而让不同 Agent 平台使用同一套计费语义。

## 计数器模型

- `net_rx_bps` 和 `net_tx_bps`：图表使用的当前速率；
- `net_rx_bytes` 和 `net_tx_bytes`：Agent 在所选网卡集合上观测到的累计计数器；
- `monthly_rx_bytes` 和 `monthly_tx_bytes`：服务端计算的当前重置周期总量。即使
  自定义重置日使周期不等同于自然月，字段名仍保持不变。

第一个样本只建立基线，贡献 0 字节。之后只有在 boot ID 不变时，才计入非负增量。
boot ID 变化或网卡计数器下降会建立新基线，绝不会产生负数或无符号回绕流量。

服务端启动时会恢复每个节点最近一次持久化计数器和周期总量，因此普通服务重启可
从上次持久化样本继续统计。如果主机和服务端都在两个持久化样本之间重启，则主机
重启前、最后持久化点之后发生的流量无法从单调计数器恢复。

## 重置周期

重置边界按 UTC 计算。配置的重置日可为 1 到 31；遇到较短月份时自动截取为当月
最后一天。例如 31 日会在 2027 年使用 2 月 28 日，在 2028 年使用 2 月 29 日。

跨过重置边界后的第一个样本从 0 建立新基线。跨越边界的单次计数器增量无法可靠
拆分，所以 Hostpin 不会把整段增量错误计入新周期。未分配时间通常最多等于一个
实时上报间隔。

## 配额模式

流量上限可与以下四种统计值比较：

| 模式 | 计费流量 |
| --- | --- |
| `sum` | 接收 + 发送 |
| `max` | 接收与发送中的较大值 |
| `up` | 仅发送 |
| `down` | 仅接收 |

节点详情始终展示双向总量、所选模式、重置日、配额百分比和警告/严重状态。公共 API
以非负整数字节返回数据。SQL 使用有符号 `BIGINT`；超出其上限的不可能值会饱和到
上限，而不是回绕为负数。

后台节点编辑器和 Agent 的高级安装问答以 GiB 输入每月流量额度，支持小数，`0`
表示不限量。Hostpin 在提交时换算为整数字节，因此已有数据无需迁移，原生 API、
数据库和 Komari 兼容字段仍保持字节单位。

默认主页会按节点的流量计算方式显示本月已用 GiB 和配额使用率。卡片视图和表格
视图使用同一进度条；使用率达到 85% 时提示警告，达到 100% 时显示危险状态。

## 流量校正

管理员可在“后台 → 节点 → 编辑 → 流量校正”中直接填写本周期应显示的下载与上传
总量，并选择 B、KiB、MiB、GiB 或 TiB。Hostpin 根据 Agent 原始周期总量计算并保存
有符号差值，而不是改写 Agent 计数器。

- 校正仅绑定当前 UTC 重置周期；进入下个周期后自动失效；
- 后续 Agent 流量继续在校正值上累加；
- 公共节点状态、实时推送、原生历史响应和流量告警使用校正值；
- 数据库中的原始指标历史保持不变，清除校正可立即恢复原始统计；
- 校正值、周期和操作审计会随 SQLite 备份及 PostgreSQL 迁移一起保留。

节点必须在当前流量周期内至少有一次上报，才能进行校正。这样可以避免离线节点跨过
重置边界后，将上一个周期的流量误认为当前基线。

- `internal/core/traffic_test.go`：基线、重启、回滚、重置日、服务恢复、短月、
  闰年与溢出；

  聚合和数据库迁移；

- `tests/load/main.go`：100/1,000 Agent 压力下的非零流量统计。
