# 延迟测量节点

[返回文档首页](README.md) · [English](../latency-probes.md)

Hostpin 可从多个独立网络视角测量每台被监控服务器。Probe Node 可以位于公网地区、
分公司、家庭、NAS 或 OpenWrt 路由器，只需能主动访问 Hostpin 面板，无需公网 IP。

## 连接方式

```text
私有路由器 / 地区服务器
        │
        └── 主动 WSS 或 HTTPS ──> Hostpin 服务端
              心跳
              结构化 ICMP/TCP 目标
              平均 RTT + 丢包率
```

Hostpin 永远不会主动连接 Probe Node，因此适用于 NAT、CGNAT、动态家庭地址以及
禁止所有非请求入站流量的网络。协议中没有 Shell、任意命令、二进制 URL 或反向
隧道字段。

## 三网延迟与 Probe Node

Hostpin 同时提供两种方向不同、但都只需出站网络的延迟测量：

| 功能 | 测量方向 | 显示位置 |
| --- | --- | --- |
| 三网延迟 | 每台普通监控 Agent → 电信/联通/移动测试目标 | 对应服务器的节点详情 |
| 延迟测量节点 | 家庭路由器或公共测量点 → 各台受监控服务器 | 公共延迟页和路径详情 |

三网延迟默认每 120 秒运行一轮，每条线路连续采样 4 次，保存成功样本的平均 TCP
建连时间和丢包比例。默认目标与
[CF-Server-Monitor 的默认设置](https://github.com/huilang-me/CF-Server-Monitor/blob/main/src/utils/settings.js)
中的电信、联通、移动目标保持一致；可在“管理后台 → 服务探测 → 三网延迟”中修改
目标、改用 ICMP 或单独暂停。
测试目标只下发为固定 ICMP/TCP 结构，不包含脚本或命令；公共节点接口会隐藏目标
地址。

普通 Agent 和 Probe Node 都主动连接 Hostpin，所以两种测量都不要求节点具有公网
IP。若要查看家庭路由器到各服务器的延迟，应把路由器安装为 Probe Node；若要查看
某台服务器自身到三家运营商网络的延迟，则查看该服务器的节点详情。

## 普通节点兼任延迟节点

已安装普通 Agent 的监控节点也可以同时充当延迟测量点。进入“管理后台 → 节点”，
编辑节点并开启“同时作为延迟测量节点”即可，无需重装或更换 Agent。开启后该节点会
继续采集 CPU、内存、磁盘和流量，同时领取延迟矩阵中的固定 ICMP/TCP 任务。

关闭开关只停止新的延迟测量，不会删除主机监控、节点身份或已有延迟历史。延迟节点
页面中的“停用延迟”具有相同效果。路由器等只需要测量延迟的设备仍建议使用
`--probe-node`，因为纯测量模式不会初始化完整的系统指标采集器，占用更低。

## 安装

Linux、OpenWrt、常见 NAS、macOS 和 FreeBSD：

```sh
curl -fsSL https://monitor.example.com/install.sh | sh -s -- --probe-node
```

Agent 会询问 PIN、展示名称、分组、地区、标签和公开/私有状态；“私有”表示保存后
节点的“隐藏”开关处于开启状态。高级设置还可配置备注、国家、并行探测上限和签名
自动更新。生成的安装身份和独立节点凭据保存在本地，PIN 只用于首次注册。

Windows：

```powershell
Invoke-WebRequest -UseBasicParsing 'https://monitor.example.com/install.ps1' -OutFile .\hostpin-install.ps1
.\hostpin-install.ps1 -ProbeNode
```

## 配置目标

进入“管理后台 → 延迟节点”：

1. 确认测量节点在线，并选择公开或私有可见性。
2. 选择一台被监控服务器作为目标。
3. 设置 ICMP 或 TCP、目标地址、每轮样本数、间隔和超时。
4. 选择该路径是否可出现在公共延迟矩阵中。

每个延迟目标关联一台被监控服务器，并下发给所有已连接的测量节点，包括纯 Probe
Node 和已开启延迟测量的普通节点。默认每轮采样
3 次。Hostpin 保存成功样本的平均值和丢失百分比；整轮失败记录为 100% 丢包。

目标地址不必等于服务器检测到的公网 IP，但 v1 中同一个地址会下发给所有 Probe
Node。如果站点只部署了能访问同一内网的家庭/办公室测量点，可以填写内网地址；
如果同时存在公网和家庭测量点，应填写所有测量点都能访问的公网域名或 IP。无法
访问该地址的测量点会记录失败。每个 Probe Node 单独设置地址覆盖属于后续版本范围。

## 公共和私有数据

测量节点的“私有”状态与节点的“隐藏”开关是同一项设置。只有同时满足以下条件，
路径才会显示在 `/latency`：

- 测量节点未隐藏；
- 被监控服务器未隐藏；
- 延迟目标标记为公开。

未认证响应会移除目标地址，并将详细网络错误替换为通用失败信息。管理员可查看隐藏
测量点、私有目标、准确地址和原始错误。

## 平台注意事项

- ICMP 调用本机 `ping`。精简 OpenWrt 镜像需要先安装，并允许 Agent 服务账户
  执行它。
- TCP 目标使用 `host:port`；IPv6 需加方括号，例如 `[2001:db8::1]:443`。
- TCP RTT 测量连接建立时间；当 ICMP 被过滤时，通常应优先使用 TCP。
- Probe-only 模式不会初始化 CPU、磁盘、GPU 或网络指标采集器，因此内存和 CPU
  占用低于完整 Agent。
- WebSocket 被阻止时，Agent 会通过出站 HTTP POST 提交心跳和结果，并使用指数
  退避重连。
